Optimasi Memori & GC di Lucee CFML

Strategi penulisan kode berkinerja tinggi untuk efisiensi JVM Heap dan minimalisasi pemicuan Garbage Collector.

Gunakan Tombol Panah Kanan/Kiri pada Keyboard

1. Arsitektur Memori JVM

Fondasi Dasar

Stack Memory

  • Menyimpan **tipe data primitif** dan **reference pointer**.
  • Siklus hidup singkat (sesuai eksekusi *function/thread*).
  • **Sangat Cepat** & Bebas dari Garbage Collector.

Heap Memory

  • Tempat tinggal **semua Objek** (Struct, Array, CFC, Query, String).
  • Dikelola sepenuhnya oleh **Garbage Collector (GC)**.
  • Alokasi liar memicu *GC Overhead* & *Latency Spikes*.

2. Rahasia: Escape Analysis

Mekanisme JVM

Bagaimana JVM menyimpan objek di Stack tanpa memicu Garbage Collector?

Scalar Replacement oleh JIT Compiler (C2)

Jika JVM mendeteksi objek dibuat lokal dan TIDAK "KABUR" (tidak di-return atau diakses thread lain), objek dipisah menjadi variabel primitif lokal dan dialokasikan ke Stack!

Syarat Agar Lolos Escape Analysis:

  • Gunakan var / local scope secara ketat.
  • Jangan passing objek ke variabel eksternal / global scope.
  • Batasi masa hidup objek hanya di dalam fungsi internal.

3. Peran `var` & `local` Scope

Lucee Scoping

Tanpa `var` (Unscoped)

Variabel otomatis bocor ke scope variables (CFC Instance Level).

Dampak: Data bertahan di Heap selama objek CFC hidup. Penyebab utama Memory Leak di aplikasi Lucee/CFML.

Menggunakan `var` / `local`

Variabel terkunci di dalam Local Scope fungsi.

Dampak: Memori langsung dibebaskan begitu fungsi selesai. Buka jalan optimasi *Escape Analysis* JVM.

4. Strategi Utama Penulisan Kode

Best Practices
1. Hindari Instansiasi Objek dalam Looping Ketat

Jangan membuat Struct/Array baru di dalam perulangan ribuan kali. Lakukan *reuse* variabel.

2. Manipulasi String dengan StringBuilder

Penggabungan String (&=) membuat objek String baru setiap kali berjalan. Gunakan Java StringBuilder untuk penggabungan skala besar.

3. Gunakan Query Stream / Cursor Data

Hindari memuat seluruh record database ke dalam Heap sekaligus. Manfaatkan streaming batching.

5. Contoh Kode: Scoping & Allocation

Studi Kasus 1 & 2
❌ BURUK: Kebocoran Scope & Loop Allocation
public void processBatch(array itemIds) {
    // BURUK: 'payload' bocor ke variables scope!
    // Membuat Objek Struct baru di Heap per iterasi
    for (id in itemIds) {
        payload = {
            id: id,
            processedAt: now()
        };
        sendToQueue(payload);
    }
}
✅ BAIK: Local Scope & Reuse Data
public void processBatch(array itemIds) {
    // BAIK: Hitung waktu sekali & hindari struct wrapper
    var currentTime = now();
    
    for (var id in itemIds) {
        // Melewatkan primitif langsung (Zero Heap Allocation)
        sendToQueueDirect(id, currentTime);
    }
}

6. Contoh Kode: String & Stream Query

Studi Kasus 3 & 4
❌ BURUK: Concat String `&=` dalam Loop
public string buildCsv(array records) {
    var csvContent = "";
    // BURUK: Meminta objek String baru di Heap per loop
    for (var row in records) {
        csvContent &= row.id & "," & row.name & "#chr(10)#";
    }
    return csvContent;
}
✅ BAIK: Java StringBuilder Native
public string buildCsv(array records) {
    // BAIK: StringBuilder mengelola buffer elastis
    var sb = createObject("java", "java.lang.StringBuilder").init();
    
    for (var row in records) {
        sb.append(row.id).append(",")
          .append(row.name).append("#chr(10)#");
    }
    return sb.toString();
}

Kesimpulan & Action Plan

Rangkuman

Ringkasan Praktik Terbaik:

  1. Gunakan var pada setiap variabel di dalam method untuk mengunci scope ke tingkat lokal.
  2. Hindari membuat Objek Struct/Array/CFC baru secara berulang di dalam looping.
  3. Manfaatkan StringBuilder untuk manipulasi string berukuran besar.
  4. Gunakan streaming / batching pada pemrosesan query ribuan baris.
  5. Batasi penggunaan scope global (session, application) hanya untuk identifier sederhana.
